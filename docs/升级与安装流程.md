# DSH 服务升级 + dsh-long-plugins 安装/重装流程

> 适用环境：Synology NAS（本机实际路径示例），其他平台把 `/volume1/dsh`、`/volume1/npm/global` 换成你的实际路径即可。
>
> 适用范围：**DSH 核心升级**、**dsh-long-plugins 安装 / 重装 / 更新**、**升级后功能丢失排查**。

---

## 目录结构速览（先搞清楚三层关系）

| 层 | 路径 | 作用 | DSH 升级影响 |
|---|---|---|---|
| ① 插件源码 + git 仓库 | `/volume1/dsh/plugins/dsh-long-plugins/` | 你的代码（带 git 历史、Release tag） | ❌ **不会被覆盖** |
| ② 插件安装副本 | `/volume1/dsh/profiles/web/node_modules/dsh-long-plugins/` | 实际运行的文件（源码的复制） | ⚠️ **会被重建**（升级后需重新同步） |
| ③ DSH 核心 | `/volume1/npm/global/lib/node_modules/@deepseek-ai/dsh/` | DSH 主程序 | ✅ 升级目标本身 |

**核心结论**：你的代码在 ①（git 仓库），升级 DSH **不会覆盖**；升级后只需让 ② 重新从 ① 复制（`pnpm install`）即可，功能全部保留。

## 一、DSH 服务升级

### 1. 备份本地配置（重要）

profile 的 `cordis.patch.yml` 含你的 trustedHosts / skillsRoot / 识图配置，升级前备份：

```sh
cp /volume1/dsh/profiles/web/cordis.patch.yml /volume1/dsh/profiles/web/cordis.patch.yml.bak-$(date +%Y%m%d)
```

### 2. 升级 DSH 核心

```sh
export PATH=/volume1/@appstore/Node.js_v22/usr/local/bin:/volume1/npm/global/bin:/volume1/dsh/bin:/bin:/usr/bin:$PATH

# 升级 dsh 核心（版本号按实际，例：0.1.0-rc.6 → 新版本）
npm install -g @deepseek-ai/dsh@latest

# 更新 profile 依赖（会让 ② 安装副本按 file: 重新从 ① 复制最新源码）
cd /volume1/dsh/profiles/web
pnpm install
```

### 3. 确认本地配置还在

```sh
# 检查 dsh-long-plugins 配置段是否还在（不在就从备份恢复）
grep -A5 "dsh-long-plugins" /volume1/dsh/profiles/web/cordis.patch.yml
```

### 4. 重启服务

```sh
/volume1/dsh/start.sh
# 或手动：
# 先杀旧进程：pkill -f "lib/bin.js web"
# 再启动（保留 --expose-internals 和 --trusted-host 参数，见 start.sh）
```

### 5. 验证

```sh
curl -s -o /dev/null -w "%{http_code}\n" http://127.0.0.1:3080/   # 期望 200
# 功能路由：
curl -s -o /dev/null -w "workspace: %{http_code}\n" -H "Host: 127.0.0.1:3080" -H "Origin: http://127.0.0.1:3080" http://127.0.0.1:3080/api/dsh-uploads/workspace
curl -s -o /dev/null -w "skill-docs: %{http_code}\n" -H "Host: 127.0.0.1:3080" -H "Origin: http://127.0.0.1:3080" http://127.0.0.1:3080/dsh-skill-docs/skill-docs
curl -s -o /dev/null -w "balance: %{http_code}\n" -H "Host: 127.0.0.1:3080" -H "Origin: http://127.0.0.1:3080" http://127.0.0.1:3080/dsh-token-usage/balance
```

> ⚠️ 升级后浏览器需**强刷**（Ctrl/Cmd+Shift+R）拉取新版客户端 bundle。

## 二、dsh-long-plugins 全新安装（新机器）

```sh
# 1. 拉源码
git clone https://github.com/jackylong1987/dsh-long-plugins.git
cd dsh-long-plugins

# 2. 一键安装（自动注入 package.json 依赖/bundles + cordis.patch.yml 配置 + pnpm install）
./install.sh web "$HOME/.dsh"
#   本机（NAS）实际是：
#   ./install.sh web /volume1/dsh
```

`install.sh` 自动完成：
- clone / 更新插件源码
- profile `package.json` 加 `file:` 依赖 + bundles 加 `dsh-long-plugins`
- profile `cordis.patch.yml` 自动追加 dsh-long-plugins 配置段（trustedHosts / skillsRoot）
- `pnpm install`

**安装后仍需确认**（install.sh 的提示）：
1. `cordis.patch.yml` 里 dsh-long-plugins 配置是否完整（尤其 `trustedHosts: !!js ctx.webRuntime.trustedHosts`）
2. `skillsRoot` 是否指向你的技能目录（默认 `<DSH_HOME>/skills`）
3. 用带 `--expose-internals` 的方式重启（`start.sh` 已带）

## 四、常见问题排查

### Q1: 升级后输出文件/技能文档/余额不见了？
多半是 ② 安装副本没重建：
```sh
cd /volume1/dsh/profiles/web && pnpm install
```

### Q2: 余额不显示？
1. 确认 `/dsh-token-usage/balance` 路由 200（见第一节验证）
2. 浏览器强刷

### Q3: 提问窗口不弹出 / 界面异常？
- 先强刷（多为浏览器缓存了旧 bundle）
- 仍异常 → 确认 dsh-long-plugins 安装副本与源码一致：
  ```sh
  diff /volume1/dsh/plugins/dsh-long-plugins/client/client.js /volume1/dsh/profiles/web/node_modules/dsh-long-plugins/client/client.js
  ```

### Q4: 服务启动失败 / 崩溃？
- 看日志：`tail -50 /volume1/dsh/dsh.log`
- 常见原因：`cordis.patch.yml` 配置损坏（从备份恢复）、端口被占、`--expose-internals` 缺失

### Q5: 升级 DSH 后核心 patch 丢了？
早期版本在核心包打过补丁（如 StatsLine 余额），**升级核心会覆盖**。但当前余额功能已在插件内（composer.dock chip），**不再依赖核心 patch**——一般无需重新打。

## 五、发布新版本（攒批发布流程）

```sh
cd /volume1/dsh/plugins/dsh-long-plugins
# 1. 提交改动
git add -A && git commit -m "feat: ..." && git push origin main

# 2. 升版本号（例 1.0.1 → 1.0.2）
python3 -c "import json; d=json.load(open('package.json')); d['version']='1.0.2'; json.dump(d,open('package.json','w'),indent=2,ensure_ascii=False)"
python3 -c "import json; d=json.load(open('dsh.plugin.json')); d['version']='1.0.2'; json.dump(d,open('dsh.plugin.json','w'),indent=2,ensure_ascii=False)"

# 3. 提交 + 推 main + 打 tag + 推 tag
git add package.json dsh.plugin.json
git commit -m "chore: bump version to 1.0.2"
git push origin main
git tag -a v1.0.2 -m "v1.0.2: ..."
git push origin v1.0.2

# 4. 创建 GitHub Release（用 token）
#    API: POST /repos/jackylong1987/dsh-long-plugins/releases
#    或直接让 AI 助手代劳（"发版本"）
```
